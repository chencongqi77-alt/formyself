# 评价方案、数据缺口与最小补证

> 当前已有的是结构校验、数据契约测试和原型。它们可证明“处理边界是否被执行”，不能自动证明“历史解释正确率”或“用户学习效果”。

## 一、现有评价能说明什么

| 现有材料 | 能说明 | 不能说明 |
| --- | --- | --- |
| 来源/公开数据校验 | 文件、字段、关系、来源定位和治理条件符合契约 | 每一条历史叙事的学术正确性 |
| job 与事实包测试 | 私有路径、可见性、时空/语义约束、状态迁移得到规则约束 | 规则对真实传记材料的召回率和精确率 |
| release manifest | 输入快照、记录包和派生文件可被版本化追踪 | 前端使用者理解了这些证据 |
| 前端数据/渲染测试 | 载荷可被读取，模块语义不被代码明显破坏 | UI 的可用性、教学效果或用户信任 |
| 候选规模计数 | 已处理或筛选的规模 | 候选对应真实事实的比例 |

## 二、短期最值得补的三组材料

### 1. 已发布事件的来源抽样审计

目标不是重新考证全部历史，而是把“来源可追溯”转成可报告的案例证据。

建议从不同诗人、年代或事件类型中抽取 12 至 20 条已发布事件，记录：

| 字段 | 内容 |
| --- | --- |
| eventId | 被核对的公开事件 |
| 人物/地点/时间 | 页面显示值与原始字段值 |
| sourceRef | 来源 ID 与 locator |
| 可回读性 | 定位是否能打开或解析 |
| 人工判断 | 支持、需修订、定位不足、待进一步核对 |
| 修订说明 | 不更改原始证据，只记录发现 |

结果应报告样本范围和判断规则，不将小样本误写为全库准确率。

### 2. 诗境与交游候选的误差分类

若论文要讨论“防止过度推断”，应从每个候选模块各抽取一组小样本，按以下类别人工标注：

- 支持：候选语义与来源线索相符；
- 歧义：地点、人物、时间或关系无法充分消歧；
- 过度推断：题名、文本提及或弱信号被误读为更强关系；
- 数据/定位问题：来源不足、坐标不宜展示、重复或字段异常；
- 拒绝合理：严格门或界面注记正确地没有把它当作事实。

这类分析可支撑“哪些错误被隔离、哪些仍需人工审查”的讨论；在没有统一标注规范前，不能计算泛化准确率。

### 3. 两到三个可回读案例卡

每张案例卡应串起：

    受治理来源或公开记录
      -> sourceRef/定位
      -> 事件或候选关系
      -> review state
      -> release/前端载荷
      -> 交互截图

优先选择已发布行迹作为主案例；诗境和交游只做候选对照。案例卡应脱敏，不包含用户上传全文或隐私材料。

## 三、只有在需要相关结论时才做的评价

| 想写的结论 | 必须新增的研究设计 |
| --- | --- |
| 用户更易理解历史材料 | 任务测试、访谈或问卷；明确样本、任务、比较条件和分析方法 |
| 学习兴趣/教学效果提升 | 前后测或对照设计、样本与伦理安排、统计或质性分析计划 |
| 自动抽取准确率 | 金标准数据、双人/多人的标注协议、一致性报告、precision/recall 与错误分析 |
| 关系图优于传统文本 | 可比较的阅读任务、完成质量/时间、受试者反馈 |
| 地图坐标历史准确 | 地名专家复核、历史—现代映射依据和空间不确定性表达 |

如果短期不能做这些工作，论文应把贡献收束为“框架、过程、案例和边界”，而不是用没有的评价替代结论。

## 四、建议的最小交付物

为了让下一位写作 Agent 能开始组织论文，建议先补齐以下文件：

1. published-event-audit.csv 或等价 Markdown 表；
2. poem-world-candidate-audit.csv；
3. social-candidate-audit.csv；
4. case-cards.md，包含两个已发布行迹案例和一个候选对照；
5. figures-manifest.csv，记录所有截图元数据；
6. literature-search-log.md，记录关键词、数据库、筛选规则和最终引用。

其中前五项只需引用公开数据或经过许可的脱敏材料；不要把 raw upload、私有提示或模型响应放入论文附件。

## 五、验收门

在写“结果/讨论”前，检查：

- 每个结果表都有数据状态；
- 每个案例至少能回到一项来源定位或明确标为候选；
- 每张截图有数据版本和日期；
- 所有规模数字都说明是 published、candidate、过滤后候选还是展示层记录；
- 任何涉及学习效果、准确率或史实正确性的句子都有独立评价材料。
