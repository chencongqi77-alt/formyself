# 论文写作交接材料包

> 快照日期：2026-08-21  
> 用途：为后续 Agent 或作者选择论文方向、组织材料和补足证据提供依据；本包不代写论文，也不复制私有上传文本、提示词或模型输出。

## 建议的主方向

当前最稳妥的方向是：

> **从受治理数字资产到可追溯交互式视据：证据优先的古诗词知识呈现框架与多视图案例**

这里的“交互式视据”是本项目的工作定义：它是保留来源定位、审查状态、语义边界和版本信息的派生交互呈现；地图、关系图或阅读卡本身不自动构成历史证据。

这个方向适合短期收尾，因为项目已有可核验的处理边界、公开五表、私有作业基础线，以及多个交互原型；它不要求把论文写成算法论文或前端实现说明。

## 使用顺序

1. 先读 [01_PROJECT_SNAPSHOT.md](01_PROJECT_SNAPSHOT.md)，确认哪些内容已经验证、哪些只是候选预览、哪些仍是设计目标。
2. 读 [02_ASSET_TO_INTERACTIVE_EVIDENCE_FLOW.md](02_ASSET_TO_INTERACTIVE_EVIDENCE_FLOW.md)，作为论文中“从数字资产到交互式视据”的简化方法图。
3. 用 [03_DIRECTION_DECISION_CARDS.md](03_DIRECTION_DECISION_CARDS.md) 选择唯一主问题与贡献边界。
4. 用 [04_CLAIM_EVIDENCE_MATRIX.md](04_CLAIM_EVIDENCE_MATRIX.md) 检查每一句核心主张是否有材料支撑。
5. 用 [05_CASE_AND_FIGURE_INVENTORY.md](05_CASE_AND_FIGURE_INVENTORY.md) 组织案例、截图、表格和附录。
6. 若准备写“有效性”或“教育效果”，必须先完成 [06_EVALUATION_GAPS_AND_MINIMUM_EVIDENCE.md](06_EVALUATION_GAPS_AND_MINIMUM_EVIDENCE.md) 中相应的补证。
7. 用 [08_RELATED_WORK_COLLECTION_BRIEF.md](08_RELATED_WORK_COLLECTION_BRIEF.md) 收集外部相关工作，避免把项目文档当作文献综述。
8. 写作和交接时遵守 [07_WRITING_GUARDRAILS_AND_HANDOFF.md](07_WRITING_GUARDRAILS_AND_HANDOFF.md)。

## 必须统一的三种状态

| 状态 | 可用措辞 | 不能推出的结论 |
| --- | --- | --- |
| 已验证实现 | 已实现、已校验、可复跑的处理或发布机制 | 不等于所有历史解释均经学术人工复核，也不等于学习效果已验证 |
| 候选预览 | 已生成并可交互展示的候选或探索性原型 | 不等于正式发布史实、准确率已证实或可自动生成史实 |
| 设计目标 | 后续架构、拟议能力、未来工作 | 不能写入结果或核心贡献 |

状态必须按数据层或交互模块分别标注，不能把整个项目笼统称为“已发布”。

## 本包的边界

- 聚焦数据治理、证据链、语义分层和交互呈现，不展开代码实现、组件设计或前端框架细节。
- 只引用仓库内可公开审查的结构、清单、校验结果与公开数据；私有 job 只可用脱敏结构、哈希和定位方式说明。
- 不将模型、OCR、网页搜索结果或题名匹配直接说成历史事实。
- 不将行迹、诗歌空间与社会关系视作同一种“地理事实”。

## 当前建议的论文骨架

1. 问题：数字资产转成交互知识呈现时，如何不丢失来源、状态与不确定性。
2. 框架：受治理资产、证据定位、候选/事实分流、派生发布、交互视据。
3. 语义分层：生平行迹、作品空间与人物关系的不同含义。
4. 案例：以已发布行迹为主，候选诗境和交游模块为补充对照。
5. 审计与局限：当前验证记录、可复现锚点、尚未完成的人工抽样审计与用户研究。

详细材料及不可越过的表述边界见本目录其余文件。
