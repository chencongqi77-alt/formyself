# 选题候选与决策卡

> 目的：帮助后续 Agent 选择一个可在短期内由现有证据支撑的方向，而不是把所有模块塞进同一篇论文。

## 推荐方向：证据优先的多视图知识呈现框架

**题目草案**

> 从数字资产到交互式视据：证据优先的古诗词知识呈现框架与多视图案例

**要回答的问题**

1. 如何使数字资产转成地图、关系图和阅读卡时仍可回到来源、定位和版本？
2. 如何在生平行迹、作品空间与人物交游之间保留不同的语义边界？
3. 如何通过 review state、来源定位和派生发布机制，使可读性不以抹平不确定性为代价？

**现有支撑**

- 已验证的来源准入、公开五表、私有作业和校验机制；
- 已存在的行迹、诗境和交游交互原型；
- 可复现的状态字段、manifest、计数与验证命令。

**仍需补充**

- 两到三个案例的人工来源抽样审计；
- 论文所需的外部相关工作；
- 视图层直接暴露来源与状态的截图/证据说明。

**适合的论文类型**

短篇数字人文、教育技术/信息可视化的系统设计与案例研究，或项目性小论文。

## 方向 B：私有传记上传到私有路线草图的可信处理

**题目草案**

> 面向古典文学传记材料的证据定位与私有路线草图生成：一个可复跑处理基线

**强项**

- 输入隔离、同意、SHA-256、文本提取、阻断策略、规则化候选与私有输出的边界很清楚；
- 可展示扫描件阻断、文学空间不反推行迹等负例；
- 不依赖前端细节。

**关键限制**

- 当前成功终点是 private map-draft，不是公开网站；
- 没有标注语料、precision/recall 或和人工标注的正式对照；
- 不应把规则链称为模型自动补全史实。

**适用条件**

若论文更偏“可信数字资料处理”而非多视图呈现，可选此方向；需要补一个脱敏的小型案例和人工核验表。

## 方向 C：古典文学空间与关系信息的反过度推断设计

**题目草案**

> 不把诗中地点画成行迹：古典文学交互知识图中的语义分层与防错规则

**强项**

- 可将生平路线、作品地点与社会关系的区别讲得非常集中；
- 规则、schema 和候选状态为“克制性设计”提供了可查材料；
- 适合以错误类型与界面提示为中心。

**关键限制**

- 诗境和交游的多数数据仍是 candidate-preview；
- 若要声称“减少误解”或“提高理解”，必须做用户研究或专家评审；
- 不能将候选规模当作准确率。

**适用条件**

若后续能补一轮来源抽样与错误分类，这会成为很有辨识度的短论文方向。

## 暂不建议作为主方向

| 方向 | 原因 | 转为可写方向前需要补什么 |
| --- | --- | --- |
| 学习效果或教学成效 | 当前没有任务实验、访谈或前后测 | 招募对象、研究伦理、任务设计、对照和分析 |
| 模型抽取准确率 | 基础线不依赖模型；没有金标准标注集 | 标注规范、双人标注、precision/recall、误差分析 |
| 前端技术创新 | 项目核心证据不在 UI 框架或渲染算法 | 明确的性能/可用性研究问题与对照 |
| 全量社会网络分析 | 关系视图有意做了可读性裁剪，且多数为候选 | 正式关系数据集、时间/关系定义、网络分析方法 |

## 决策规则

后续 Agent 应先选定下列三个项目，再生成论文大纲：

1. **唯一主张**：框架/可信处理/防错语义三选一，其他只能作补充。
2. **主案例状态**：优先选 published 行迹数据；candidate-preview 只可作为探索性对照。
3. **评价口径**：没有新增人审或用户研究时，只报告结构校验、覆盖量、筛选量与案例可追溯性，不报告准确率或学习效果。

若三项无法同时满足，应收缩题目，而不是通过增加代码细节来填补证据缺口。
