# 贡献主张—证据强度矩阵

> 使用方式：论文摘要、引言、结果和结论中的每一个重要主张，都应先在本表找到支撑材料与表述上限。

## 一、可主张的内容

| 预期主张 | 证据强度 | 当前可用材料 | 推荐写法 |
| --- | --- | --- | --- |
| 建立了证据—候选—审查—派生视图的分层框架 | 强 | 数据边界、schema、私有 job、公开五表契约 | “项目实现了/采用了证据优先的分层处理框架” |
| 处理过程保留了来源快照、定位、状态和版本信息 | 强 | source/raw manifest、fact package、release manifest、校验器 | “关键数据对象保留可回读的 provenance 字段与验证入口” |
| 生平路线与文学空间关系被显式区分 | 强 | 受控 predicate、claimClass、验证器与自动测试 | “将易混淆关系做语义隔离，并禁止由诗题/诗句单独推导到访” |
| 已构建多个交互视据原型 | 中 | 行迹、诗境、交游路由及前端载荷 | “构建了包含已发布数据与候选预览的多视图原型” |
| 系统具备扩展潜力 | 中 | 多人物公开五表、候选筛选量、发布清单 | “展示了多类资产和多视图的扩展接口/实例” |
| 公开五表具有可复查的数据完整性 | 强 | 2026-08-21 的公开校验与 dry-run | “本次快照下通过结构、关系和来源校验” |

## 二、只能谨慎陈述的内容

| 内容 | 允许的说法 | 不允许的说法 |
| --- | --- | --- |
| 诗中世界地点 | “文本地点候选、展示近似、区域注记” | “诗人确定到访/在此创作” |
| 社会关系图 | “带证据线索的关系阅读候选” | “完整且已定论的社会网络” |
| 私有自动地图 | “规则化私有路线草图” | “自动发布的历史路线图” |
| 事件时间 | “史料标签、范围或顺序” | “全部已精确换算为公历” |

## 三、目前不能作为结论的内容

| 不能主张的结论 | 原因 | 如要主张，至少需要 |
| --- | --- | --- |
| 提升学习兴趣、理解或教学效果 | 没有用户研究 | 任务实验、访谈或问卷，以及相应的伦理/样本说明 |
| 模型或规则的准确率、优于基线 | 没有金标准和正式对照 | 标注集、标注一致性、precision/recall、误差分析 |
| 所有历史事实均已学术审定 | candidate 与 published 状态并存 | 人工来源抽查、审核记录和范围说明 |
| 所有古今地名已消歧、坐标精确 | 歧义和 display-only/近似展示仍存在 | 地名审校与空间不确定性研究 |
| 已实现完整自动发布体系 | 通用 release/exporter 仍为规划 | 实现、审计与端到端 release 验收 |

## 四、论文中建议使用的“状态句式”

| 状态 | 推荐句式 |
| --- | --- |
| 已验证实现 | “在 2026-08-21 的数据快照中，该机制通过了相应结构与来源校验。” |
| 候选预览 | “该模块以 candidate-preview 形式提供探索性阅读，不将候选提升为已发布史实。” |
| 设计目标 | “该能力被纳入后续 release 架构，尚不构成本研究已完成的结果。” |
| 负例/阻断 | “系统选择阻断或保留歧义，而非以自动补全替代证据。” |
